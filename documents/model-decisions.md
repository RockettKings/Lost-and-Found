# Model Decisions, Req 5 and Req 13

Nov 20, 2026 · Jaycob Campos

This file settles the three model decisions the [Sprint Plan](sprint-plan.md)
assigns to the ML lead: where the weights file lives, the minimum accuracy, and
the confidence threshold. It is written by hand and **is not overwritten**.
`documents/model-results.md` and `documents/model-overnight.md` are generated by
`cnn.py` and `overnight.py`, so each training run replaces them - nothing
durable belongs there.

Lydia's Req 13 tests in Sprint 3 assert against the numbers in the
[Req 13 acceptance gates](#req-13-acceptance-gates) section below.

## Decision 1: where the model weights file lives

**In the repository root, committed, as `best_weights_resnet18_base.pt`.**

- 44.8 MB. GitHub warns above 50 MB and refuses above 100 MB, so it goes in Git
  directly; no Release asset or S3 object is needed.
- `.gitignore` ignores `best_weights_*.pt` and then un-ignores this one filename,
  so the other local checkpoints stay out of the repository.
- `app/model.py` reads `MODEL_WEIGHTS_PATH` and falls back to this file, so a
  fresh clone answers Req 5e without training first. Setting the variable serves
  a different checkpoint, for example one kept outside the repository.
- Nothing is downloaded at load time (Req R6). The architecture is built empty
  by `torchvision.models` and filled from this file, so a cold start works
  offline.

## Decision 2: minimum accuracy

Two separate floors, because Req 13 scores a 93-photo fixture and the ship
decision scored the full 1,147-photo test split.

| Gate | Measured on | Floor | Last measured |
| --- | --- | --- | --- |
| Ship / no-ship | full held-out test split, 1,147 photos | **75% top-1** | 81.1% |
| Req 13 regression | `tests/sample_photos/`, 93 photos | **70% top-1** | 79.6% |

The shipped checkpoint measures 78.8% validation / 81.1% test, which clears the
ship floor. 75% is the fallback trigger the Sprint 2 checkpoint called for: a
model below it does not ship, and the post form keeps its plain category field
with no prefill, which is what `app/posts/guess.py` already degrades to when the
model is unavailable.

The Req 13 floor is lower than the ship floor on purpose. 93 photos give a
standard error of about 4 points, so a model that truly scores 81% will land
between roughly 73% and 88% on this fixture by chance alone. A 70% floor is
about two and a half standard errors below the measurement: it passes a healthy
model every time and still catches a real regression, such as a checkpoint
trained on a different category list or a broken preprocessing step.

**A sample-set score between 70% and 75% is a passing test, not a passing
model.** Only the full test split decides whether the model ships.

## Decision 3: confidence threshold

**`CONFIDENCE_THRESHOLD = 0.60`, defined in `app/model.py`.**

A guess at or above 0.60 fills the category field on the post form (Req 5f).
Below it, the field is left blank and the poster chooses. Measured on the 1,115
validation photos:

| Threshold | Fills the field | Correct when it fills |
| --- | --- | --- |
| 0.50 | 61.6% | 95.3% |
| **0.60** | **54.3%** | **96.9%** |
| 0.70 | 43.8% | 98.6% |
| 0.80 | 34.5% | 99.2% |

0.60 fills the field for over half of uploads and is right about 97% of the time
when it does. Label smoothing during training flattens the softmax, so these
confidences are lower than an unsmoothed model's - do not carry this number over
to a model trained without it.

The same thresholds re-measured on `tests/sample_photos/` agree: 0.60 fills
55.9% of the 93 photos and is correct 98.1% of the time when it does.

A wrong prefill costs the poster one dropdown change (Req 11 keeps the field
editable), while a blank field costs every poster one selection. That trade is
why the threshold sits at 0.60 rather than 0.80.

## Req 13 acceptance gates

Req 13 is "category guess on held-out photos," owned by Lydia in Sprint 3. The
fixture is `tests/sample_photos/`: 93 photos, three per category, drawn from the
test split that produced the 81.1% number, so the model has never seen them.
`tests/sample_photos/README.md` covers how they were selected and licensed.

A passing Req 13 run asserts all three:

1. **Top-1 accuracy ≥ 70%** over the 93 photos, via `app.model.predict()`.
2. **Precision when the field fills ≥ 90%**: of the photos where confidence
   reaches `CONFIDENCE_THRESHOLD`, at least 90% are the right category.
   Currently 98.1%.
3. **Every returned category is in `app.categories.CATEGORIES`**, and every
   confidence is between 0 and 1.

Do not assert a per-category accuracy. Several categories hold only three sample
photos, so one miss is a 33-point swing; look-alike pairs such as
bracelet/necklace and eyeglasses/sunglasses miss regularly and are expected to.

Do not assert an exact accuracy figure either. Re-measure and update this file
when the served checkpoint changes.

## Open follow-up: a better checkpoint exists

The overnight sweep found EfficientNet-B0 configurations reaching 84.5%
validation, about 6 points above the served ResNet18, in a 15.7 MB file rather
than 44.8 MB. It is not served yet because its **test** accuracy has never been
measured - the test split is scored once, on the chosen model, and that budget
was spent on ResNet18.

Swapping the served checkpoint means: score the candidate on the test split
once, re-measure the threshold table on validation, re-measure the three gates
above on `tests/sample_photos/`, then update this file, `app/model.py`'s
`DEFAULT_WEIGHTS`, and the `.gitignore` un-ignore line. `app/model.py` already
loads either architecture, so no code change is needed to switch.

## How to re-measure

```sh
# Full test split and the confusion matrix (Req 5d). Writes model-results.md.
.venv/bin/python cnn.py

# The three Req 13 gates on the shipped fixture.
.venv/bin/python -m pytest tests/test_category_guess.py -q
```
